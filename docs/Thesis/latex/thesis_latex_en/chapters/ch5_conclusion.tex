\chapter{Conclusion and Future Work}
\label{ch:conclusion}

This chapter synthesizes the primary research outcomes and core contributions of the thesis entitled ``A Cognitive Two-Tier Architecture for Automated Threat Detection and Contextual Response using Agentic AI'' (SENTINEL). The content summarizes empirical evaluation results aligned with the three research questions, affirms scientific and practical contributions, transparently addresses existing architectural limitations, and outlines future research directions to advance Security Operations Center (SOC) defense capabilities.

\section{Summary of Research Achievements}
\label{sec:conclusion_summary}

Comprehensive empirical evaluation across 25,799 telemetry events from the CSE-CIC-IDS2018 benchmark~\cite{ids2018}, HTTP Layer 7 events from CSIC 2010, multi-stage APT scenarios from DAPT2020~\cite{dapt2020}, and a 300-sample balanced ablation dataset demonstrates that the SENTINEL system successfully resolves the three strategic research questions formulated in Chapter 1.

Regarding the first research question (RQ1) on wire-speed filtering pipeline performance and economics, quantitative measurements confirm that the multi-tiered architecture effectively overcomes compute resource bottlenecks. First, regarding efficiency (RQ1), SENTINEL successfully offloaded 92.2\% of telemetry events (only 389/5000 required LLM invocation) at wire-speed with an average Tier 1 latency below 0.40\,ms. While global End-to-End average latency was observed to be 7.8\% slower than anticipated due to continuous context switching, the architecture successfully maintains throughput exceeding 2,500 flows/s while freeing GPU VRAM by over 75\%.

Regarding the second research question (RQ2) on AI security guardrails and cryptographic non-repudiation, Delimited Data Encapsulation using unique random Nonce delimiters combined with deterministic Guardrails successfully neutralizes 100\% of log-substrate prompt injection attack vectors~\cite{promptinjection2023, owasp_llm2025}. This mechanism forces the language model to process raw inputs strictly as passive data, completely preventing inference manipulation risks. Concurrently, HMAC-SHA256 cryptographic hash-chaining~\cite{hmac1997} sequentially sealing each audit log entry guarantees non-repudiation and tamper-evident forensic audit trail integrity against post-compromise tampering.

Regarding the third research question (RQ3) on stateful agent reasoning, ATT\&CK technique mapping, and transparent explanations, the Tier 2 LangGraph agent integrating the Foundation-Sec-8B-Instruct Q4\_K\_M model with Dual-RAG RRF rank fusion ($k=60$)~\cite{faiss2019, bm25_2009, rrf2009} across 433 STIX MITRE ATT\&CK entries achieves an ATT\&CK technique mapping accuracy of 67.33\% (on CSIC samples). Security adjudication decisions achieve 100\% action accuracy on the ablation set, completely eliminating the need for human-in-the-loop escalation (AWAIT\_HITL = 0.0\%). Reasoning logic quality evaluated by an independent Meta-Llama-3-8B judge yields 4.6/5.0, confirming transparent forensic justification while detecting and neutralizing hallucination.

\section{Scientific and Practical Contributions}
\label{sec:contributions}

This thesis provides two core contributions spanning theoretical security research and practical enterprise implementation within the domains of cybersecurity and artificial intelligence.

In terms of scientific contributions, the research proposes a Cognitive Two-Tier Hybrid Architecture harmonizing high-speed deterministic statistical algorithms at Tier 1 with stateful LLM agent reasoning engines at Tier 2. This multi-tiered structural paradigm establishes a systematic compute offloading mechanism, resolving quadratic self-attention latency bottlenecks $\mathcal{O}(N^2)$ inherent in large language models operating within continuous network telemetry streams~\cite{vaswani2017}. Furthermore, the thesis contributes a structural data encapsulation model utilizing unique random Nonce delimiters, providing architectural security guarantees against log prompt injection attacks without relying on fragile probabilistic classifiers~\cite{promptinjection2023, owasp_llm2025}. Finally, the study establishes a non-parametric quantitative evaluation methodology integrating cross-family LLM-as-a-Judge protocols and standardized RAGAS metrics tailored for local agentic security systems.

In terms of practical contributions, the thesis delivers a fully containerized open-source system prototype packaged via Docker Compose and empirically verified on accessible SME commercial hardware (an Intel Core i7 processor, 32\,GB RAM, and a single NVIDIA GeForce RTX 4060 Ti 16\,GB VRAM GPU). This design strictly adheres to Zero-Trust security principles and enterprise data sovereignty mandates within an air-gapped environment~\cite{nist80207}. The implementation features an interactive Streamlit monitoring dashboard connected to Human-in-the-Loop (HITL) queues to replace static SOAR playbooks~\cite{soar2025}, while automatically sealing forensic audit trails via HMAC-SHA256 cryptographic hash-chaining to support post-incident investigation~\cite{hmac1997}.

\section{Current System Limitations}
\label{sec:limitations}

Despite achieving positive empirical evaluation outcomes, several technical and methodological limitations of the SENTINEL system should be acknowledged transparently to define its operational boundaries.

The first limitation involves telemetry evaluation scope and log parsing capabilities. Current evaluations focus primarily on normalized NetFlow features and Layer-7 HTTP log attributes from the CSE-CIC-IDS2018 and DAPT2020 benchmarks~\cite{ids2018, dapt2020}. In real-world enterprise SOC environments, heterogeneous unstructured log sources (such as Windows Event Logs, raw Syslog, or AWS CloudTrail) necessitate sophisticated log parsing and feature extraction mechanisms.

The second limitation involves single-node hardware compute boundaries under volumetric traffic surges exceeding 100,000 events/second. Although Tier 1 successfully offloads over 80\% of baseline stream noise, the volume of escalated anomalous events to Tier 2 on a single 16\,GB VRAM GPU server may temporarily exceed the immediate inference capacity of the language model, leading to Redis Stream consumer queue elevation.

The third limitation stems from trade-offs between operational autonomy and Self-Denial-of-Service (Self-DoS) risks when executing automated IP blocking actions. To prevent accidental blocking of critical internal IP addresses or infrastructure servers caused by potential model reasoning bias, the system forces general port-based MITRE ATT\&CK detections (such as T1571) into human analyst review queues (\texttt{AWAIT\_HITL}). Mandatory analyst intervention slightly reduces absolute automation levels but serves as an indispensable safety guardrail for enterprise infrastructure protection.

The fourth limitation concerns the scope and mechanics of APT attack chain correlation. The current stateful correlation mechanism relies primarily on fixed source IP tracking across representative test scenarios. In real-world environments featuring IP rotation or distributed botnets, correlation mechanisms relying strictly on source IP addresses may experience reduced effectiveness.

The fifth limitation relates to state storage operational stability within containerized deployment environments. Audit logging and threat memory operations on SQLite databases, if not configured with appropriate synchronization modes, may encounter file lock contention or process disruption during unexpected service crashes.

\section{Future Research Directions}
\label{sec:future_work}

To address the five technical limitations identified in Section~\ref{sec:limitations}, future research and development for SENTINEL proposes five corresponding technical engineering solutions for production deployment:

First, addressing evaluation scope and parsing limitations, future work will develop an automated ingestion engine integrating template clustering algorithms (such as Drain~\cite{he2017drain} or LogParser) to parse and normalize diverse log formats into standardized feature vectors prior to pipeline processing.

Second, addressing volumetric DoS traffic surges and single-GPU bottlenecks, the system will re-implement Tier 1 filters in compiled system languages (such as Go or Rust) to elevate throughput to millions of events per second; concurrently migrating Redis Streams to partitioned disk-backed Apache Kafka clusters and upgrading Tier 2 engines to vLLM or TGI frameworks supporting PagedAttention and continuous batching for parallel GPU processing.

Third, addressing Self-DoS risks and autonomy trade-offs, research proposes applying Reinforcement Learning from Human Feedback (RLHF) based on analyst approval decisions within \texttt{AWAIT\_HITL} queues, enabling agents to continuously refine response policies and safely automate IP blocking without Self-DoS risks.

Fourth, addressing source IP correlation constraints and security tool orchestration, future work will implement specialized Multi-Agent Sub-systems combined with Graph Neural Networks (GNNs) to correlate attack chains based on technical vectors. Concurrently, the system will integrate the Model Context Protocol (MCP) standard, enabling AI agents to dynamically query and orchestrate external security tools (SIEM, EDR, eBPF Firewalls, CTI feeds), evolving SENTINEL into a fully Autonomous Enterprise SOC Command Center.

Fifth, addressing state storage stability risks, production deployments will mandate SQLite configurations in \texttt{synchronous=NORMAL} mode (strictly avoiding \texttt{WAL} mode to eliminate cross-UID permission lock crashes in Docker environments), combined with latency-based Redis consumer group backpressure monitoring to guarantee 24/7 continuous operational availability for enterprise SOCs.
