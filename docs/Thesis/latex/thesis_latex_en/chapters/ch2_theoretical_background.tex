\chapter{Theoretical Background and Literature Review}
\label{ch:theoretical_background}

This chapter presents the foundational theoretical principles of this thesis, covering: current SOC operations and the cognitive bottleneck, deterministic rules, online statistics, and Tier 1 machine learning, local large language models and Tier 2 agentic intelligence, adversarial AI security and log audit cryptography, and an overview of related work to delineate the research gap addressed by SENTINEL.

\section{Current SOC Operations and the Cognitive Bottleneck}

This section analyzes the core architectural causes of the alert overload described in Chapter~\ref{ch:introduction}. In a standard SOC model, monitoring relies on aggregating raw telemetry from sensors such as Next-Generation Firewalls (NGFW), Intrusion Detection Systems (IDS/IPS), and Endpoint Detection and Response (EDR) into a centralized SIEM platform~\cite{siem2021}, at volumes far exceeding manual human analysis capacity~\cite{bigdata2019}. The primary architectural bottleneck stems from the operational nature of these sensors: they render decisions predominantly via static signatures or deterministic rule sets. Because the cost of missing an intrusion is severe, operators are forced to lower detection thresholds. However, lowering thresholds in signature-based systems exponentially increases false positive volume in analysis queues without enhancing contextual understanding~\cite{alertfatigue2022, alahmadi2022}.

At the higher operational layer, Security Orchestration, Automation, and Response (SOAR) platforms attempt to reduce manual workload by executing pre-programmed response playbooks~\cite{soar2025}. Nevertheless, SOAR is strictly constrained by playbook rigidity: a playbook triggers successfully only when alert parameters precisely match anticipated scenarios. For complex multi-stage attack chains, novel behavioral anomalies, or unstructured evidence scattered across multiple records, SIEM, IDS/IPS, and SOAR layers collectively fail to form contextual judgments. Consequently, all unresolved cases escalate to manual analysis queues, transforming human analysts into the sole cognitive bottleneck of the entire security lifecycle.

\section{Deterministic Rules, Online Statistics, and Tier 1 Machine Learning}
\label{sec:welford}

Operating at wire-speed imposes strict algorithmic constraints on Tier 1: processing mechanisms must achieve constant $\mathcal{O}(1)$ time and memory complexity. First, a rule-based defense layer uses static set-matching and service-port lookups to instantly eliminate coarse anomalies without consuming computational resources. Next, baseline tracking applies Welford's incremental recurrence formula~\cite{welford1962} to continuously update the running mean $\mu_k$ and sum of squared deviations $S_k$ per observation, computing standard deviation $\sigma_k = \sqrt{S_k / (k-1)}$ and dynamic $Z$-scores without storing raw historical telemetry:
\begin{equation}
\label{eq:welford}
    \mu_k = \mu_{k-1} + \frac{x_k - \mu_{k-1}}{k}, \quad S_k = S_{k-1} + (x_k - \mu_{k-1})(x_k - \mu_k)
\end{equation}

Finally, Gradient Boosted Decision Tree (GBDT) machine learning models---exemplified by LightGBM~\cite{ke2017lightgbm}---provide rapid classification of multi-dimensional telemetry patterns. Combining deterministic rule filtering, $Z$-score statistical normalization, and machine learning classification creates a high-speed multi-stage defense line, ensuring high-throughput offloading while maintaining robustness against adversarial telemetry variants.

\section{Local Large Language Models and Tier 2 Agentic Intelligence}
\label{sec:local_llm}

Executing the reasoning tier entirely on-premise is mandatory to guarantee internal security data sovereignty, while imposing strict GPU memory boundaries. Quantization compresses weight representations onto a coarser integer grid, trading a minor amount of numerical fidelity for significant memory reduction~\cite{quantization2021}. Under GGUF Q4\_K\_M, the security-specialized Foundation-Sec-8B-Instruct model~\cite{foundation_sec_instruct, foundation_sec_2024} occupies approximately 7–8\,GB VRAM, preserving sufficient headroom for context buffers and retrieval indices on a local GPU.

The reasoning tier orchestrates analysis flows via a LangGraph state graph~\cite{langgraph2024}. To mitigate hallucinations and ground decisions in verifiable evidence~\cite{rag2020}, the system combines hybrid retrieval across dense vector search (FAISS)~\cite{faiss2019} and sparse keyword matching (BM25)~\cite{bm25_2009}. Retrieved candidates are fused by rank position using Reciprocal Rank Fusion (RRF)~\cite{rrf2009}:
\begin{equation}
\label{eq:rrf}
    RRF\_Score(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}
\end{equation}
enabling transparent cross-referencing of log telemetry against MITRE ATT\&CK technique codes~\cite{strom2018mitre} and NIST SP 800-61r2 incident handling guidelines~\cite{nist80061}.

\section{Adversarial AI Security and Log Audit Cryptography}
\label{sec:adversarial_theory}

Integrating Large Language Models into security operations introduces log-substrate prompt injection risks~\cite{promptinjection2023, owasp_llm2025}. Because raw log content is adversary-controlled, content-matching filters or probabilistic keyword detectors remain vulnerable to novel adversarial variants~\cite{watchtower2026}. This theoretical foundation necessitates protecting the reasoning tier via deterministic structural isolation (Delimited Data Encapsulation), establishing an absolute boundary between control instructions and untrusted telemetry.

Regarding forensic audit integrity, evidence records are sealed in sequence using HMAC-SHA256 signature chaining~\cite{hmac1997} under a local secret key. Theoretical boundaries must be precisely stated: symmetric HMAC encryption guarantees tamper-evidence and modification detection, but does not provide non-repudiation, which requires asymmetric digital signature infrastructure.

\section{Overview of Related Research and Research Gaps}

AI-driven security operations research has evolved across three main architectural paradigms, as surveyed by Zhang et al.~\cite{llmsec_survey2025}.

The first group, traditional enterprise defenses, comprises SIEM platforms such as IBM QRadar and SOAR tools like Palo Alto Cortex XSOAR~\cite{siem2021, soar2025}. These systems are complemented by online log parsers like Drain~\cite{he2017drain}, which compress syntax but cannot analyze behavioral context. Operators bear the burden of this rigidity: in interviews with SOC personnel, AlAhmadi et al.~\cite{alahmadi2022} identified poor alert quality as the primary driver of fatigue. The core strength of this baseline is low latency, a property SENTINEL's Tier 1 inherits and refines.

The second group, retrieval-augmented classification agents such as CyberRAG~\cite{cyberrag2025}, orchestrates domain-tuned classifiers behind an LLM agent, reporting over 94\% per-class accuracy on web attacks. While effective at analyzing selected events, this architecture does not address front-end triage, lacking a wire-speed filtering layer to manage incoming event volume.

The third group, multi-agent and governance-focused frameworks, includes AutoBnB-RAG~\cite{autobnb2025}, LanG~\cite{lang2026}, and Policy-Guided Threat Hunting~\cite{splunkllm2026}. AutoBnB-RAG evaluates multi-agent incident response in simulated tabletop environments (\textit{Backdoors \& Breaches}). LanG utilizes LangGraph with human-in-the-loop checkpoints and dual-layer defense (regex plus Llama Prompt Guard 2 achieving 98.1\% F1). Policy-Guided Threat Hunting employs reconstruction autoencoders and deep reinforcement learning prior to LLM contextual analysis.

A precise research gap emerges: cost-tiering exists in Policy-Guided Threat Hunting, prompt defense exists in LanG, and local execution is demonstrated across systems. However, no single architecture unifies: (1) resolving the vast majority of telemetry at a statistical/ML tier with sub-millisecond latency and offload rates reported against the attack base rate at which they were measured; (2) stateful reasoning on a local GPU under strict retrieval grounding rules; and (3) structural prompt defense paired with HMAC-SHA256 forensic sealing.
