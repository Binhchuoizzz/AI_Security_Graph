\chapter{System Design and Technical Implementation}
\label{ch:system_design_implementation}

This chapter details the research methodology, followed by the system design and experimental implementation of SENTINEL: the two-tier processing pipeline, Tier 1 wire-speed filter and Machine Learning Gate, Tier 2 stateful LangGraph agent and Threat Memory, Dual-RAG hybrid knowledge retrieval, and adversarial AI security controls with cryptographic audit sealing.

\section{Research Methodology}
\label{sec:methodology}

The thesis adopts the Design Science Research Methodology (DSRM)~\cite{peffers2007}. The core contribution of this research is a technical artefact, evaluated quantitatively through objective empirical metrics rather than purely conceptual arguments. The system is structured upon three core technical pillars:
\begin{enumerate}[leftmargin=*,label=\arabic*.]
    \item \textit{Rule-based, Statistical, and Machine Learning Pillar}: Provides wire-speed stream filtration via application signature rules (Rule-based), Welford $\mathcal{O}(1)$ online statistics~\cite{welford1962}, combined with a LightGBM Machine Learning Gate~\cite{ke2017lightgbm}.
    \item \textit{Agentic Logic Pillar}: Provides deep contextual reasoning through a LangGraph state-graph~\cite{langgraph2024} orchestrating a locally deployed Foundation-Sec-8B-Instruct model~\cite{foundation_sec_instruct} over hybrid FAISS/BM25/RRF retrieval~\cite{faiss2019, bm25_2009, rrf2009}.
    \item \textit{Adversarial Security Pillar}: Establishes a robust defensive perimeter against log-substrate prompt injection risks~\cite{promptinjection2023, owasp_llm2025} and seals evidence records via HMAC-SHA256 signature chaining~\cite{hmac1997}.
\end{enumerate}

Operational efficacy of the SENTINEL architecture is quantitatively evaluated across five core measurement dimensions: classification quality, processing latency and throughput, adversarial resistance, explanation coherence (scored independently by a judge model), and forensic audit trail integrity. Comprehensive empirical results, comparative baselines, and system limitation verifications are detailed in Chapter~\ref{ch:experiments_evaluation}.

\section{SENTINEL Architecture Overview and SOC Stack Integration}
\label{sec:architecture_overview}

SENTINEL operates under a cognitive two-tier architecture centered on computational cost-tiering. Raw telemetry from perimeter sensors streams into a Redis Stream queue and routes to Tier 1. Tier 1 serves as a stateless statistical and machine learning processing stage, resolving the majority of traffic volume at wire-speed. Among Tier 1's action vocabulary, only \texttt{ESCALATE} proceeds to Tier 2, while \texttt{BLOCK\_IP}, \texttt{ALERT}, \texttt{AWAIT\_HITL}, and \texttt{DROP} terminate at Tier 1. This grounds the offload rate definition used in Chapter~\ref{ch:experiments_evaluation}: an event is offloaded when resolved without triggering a language model invocation.

At Tier 2, the LangGraph agent~\cite{langgraph2024} performs deep contextual reasoning over the Foundation-Sec-8B-Instruct model~\cite{foundation_sec_instruct} (GGUF Q4\_K\_M quantized), integrating historical state from Threat Memory and evidence from Dual-RAG. Model outputs are bounded by a deterministic guardrail enforced to 3 action states (\texttt{BLOCK\_IP}, \texttt{LOG}, \texttt{AWAIT\_HITL}), with all records from both tiers sealed via HMAC-SHA256 signature chains~\cite{hmac1997}. SENTINEL operates as cognitive middleware between SIEM collectors and defense enforcement systems (NGFW/SOAR), absorbing stream noise at Tier 1 and providing cited justifications for escalated events at Tier 2, guaranteeing data sovereignty via air-gapped execution on a local GPU~\cite{nist80207}. \section{Tier 1: Wire-speed Filter and Machine Learning Gate}
\label{sec:tier1_mlgate}

Tier 1 operates as a stateless wire-speed perimeter layer combining application-layer signature rules and a Welford $\mathcal{O}(1)$ baseline statistical filter~\cite{welford1962} (Equation~\ref{eq:welford}). The signature engine covers 30 attack families normalized to OWASP CRS 3.3 benchmarks~\cite{owasp2021} (23 mapping to OWASP Top 10:2021; 7 targeting network/endpoint anomalies like ransomware and cryptomining). Concurrently, the Welford filter computes streaming $Z$-scores $Z = (x - \mu)/\sigma$ over flow attributes (packet rate, byte count, duration), updating baseline parameters $\mu$ and $\sigma$ to discard conforming telemetry automatically. Detailed Tier 1 processing flows are shown in Figure~\ref{fig:tier1_detail}.

\begin{figure}[htbp]
    \centering
    \makebox[\textwidth][c]{\includegraphics[width=1.18\textwidth]{images/tier1_detail.pdf}}
    \caption{Tier 1 detail diagram. (Source: Author)}
    \label{fig:tier1_detail}
\end{figure}

For high-volume repetitive traffic (DDoS, credential stuffing), the Tier 1.75 Semantic Cache hashes normalized query strings in RAM, reusing prior decisions in $<1$\,ms without recalculation overhead.

Downstream, the LightGBM Machine Learning Gate~\cite{ke2017lightgbm} evaluates non-linear feature interactions, trained on 664,674 and tested on 189,907 NetFlow telemetry records drawn from the 949,535-record CSE-CIC-IDS2018 benchmark~\cite{ids2018}. To counter evasion, the Gate clips $Z$-scores to $[-8, 8]\sigma$, imputes missing values with baseline means, and abstains to Tier 2 when distorted features exceed 30\%. Adjudications map via a 4-band confidence policy ($0.85$ / $0.65$ / $0.40$ for \texttt{BLOCK\_IP} / \texttt{ESCALATE} / \texttt{ALERT} / \texttt{LOG}), ensuring automated blocking executes only at highest confidence with signature concurrence.

\section{Tier 2: LangGraph Cognitive Agent and Threat Memory}
\label{sec:tier2_agent_fsm}

Tier 2 executes the Foundation-Sec-8B-Instruct model~\cite{foundation_sec_instruct} (GGUF Q4\_K\_M) served by a CUDA-compiled llama.cpp engine on a local GPU. Reasoning flows are orchestrated by a LangGraph state-graph~\cite{langgraph2024} across core stages: guardrail inspection (\texttt{guardrails}), context enrichment (\texttt{rag\_context}), incident triage (\texttt{llm\_triage}), technique mapping (\texttt{attack\_mapper}), and action execution (\texttt{action\_executor}) or human-in-the-loop hand-off (\texttt{human\_in\_the\_loop}). The agent state-graph is illustrated in Figure~\ref{fig:tier2_graph}.

\begin{figure}[h!]
    \centering
    \makebox[\textwidth][c]{\includegraphics[width=1.0\textwidth]{images/agentic_fsm_workflow.pdf}}
    \caption{Tier 2 agent state-graph. (Source: Author)}
    \label{fig:tier2_graph}
\end{figure}

At \texttt{attack\_mapper}, absent explicit knowledge evidence, events route to analyst review (\texttt{AWAIT\_HITL}) rather than emitting speculative actions. At \texttt{llm\_triage}, ground-truth fields are stripped from the prompt for evaluation objectivity. Input context is managed via Drain log-template mining~\cite{he2017drain} paired with token budget monitoring.

To correlate multi-stage threat activities, Tier 2 maintains Threat Memory on SQLite (rollback-journal mode preventing Docker file locking). Reputation score $S$ decays over silent period $t$: $S_{\text{new}} = S_{\text{old}} \times (1 - \lambda)^t$ where $\lambda$ is the decay rate. Upon reaching $S = 100$, Tier 1 enforces permanent block-on-sight without re-triggering Tier 2. Critical internal infrastructure addresses are whitelisted to eliminate self-inflicted Denial of Service (Self-DoS) risks.

\section{Dual-RAG Hybrid Knowledge Retrieval}
\label{sec:dual_rag}

To eliminate hallucinations, Tier 2 retrieves over a knowledge base of 433 STIX 2.1 MITRE ATT\&CK entries~\cite{strom2018mitre} and NIST SP 800-61r2 guidelines~\cite{nist80061}. Parallel channels combine FAISS~\cite{faiss2019} (Sentence-BERT~\cite{reimers2019sentence}) for dense vector intent search with BM25~\cite{bm25_2009} for sparse keyword matching of CVEs and service ports. Results are merged via Reciprocal Rank Fusion (RRF, $k=60$)~\cite{rrf2009} and injected at \texttt{rag\_context} (Figure~\ref{fig:dual_rag}).

\begin{figure}[h!]
    \centering
    \makebox[\textwidth][c]{\includegraphics[width=1.12\textwidth]{images/dual_rag.pdf}}
    \caption{Dual-RAG hybrid retrieval and evidence-anchoring guardrail. (Source: Author)}
    \label{fig:dual_rag}
\end{figure}

Retrieved text is sanitized by Unicode normalization, markup stripping, and command neutralization to prevent indirect injection. At output, an evidence-anchoring guardrail cross-references proposed MITRE ATT\&CK codes against batch evidence. Unanchored codes are forced to \texttt{N/A} and deferred to \texttt{AWAIT\_HITL}, so that no identifier absent from the retrieved evidence is ever acted upon.

\section{Adversarial AI Security and Cryptographic Audit Sealing}
\label{sec:ai_security_hmac}

Log prompt injection attacks~\cite{promptinjection2023, owasp_llm2025} embed control instructions inside raw log fields (User-Agent, URI). SENTINEL mitigates this via Delimited Data Encapsulation using dynamic per-batch random Nonce tokens, preventing delimiter escape (Figure~\ref{fig:nonce_hmac}). Three deterministic boundary validators guard system integrity: Data (filters malformed logs), Decision (enforces Pydantic \texttt{LLMDecision} and blocks internal IP bans), and Feedback (Zero Trust for AI rules).

\begin{figure}[h!]
    \centering
    \makebox[\textwidth][c]{\includegraphics[width=1.08\textwidth]{images/nonce_hmac.pdf}}
    \caption{Input Nonce encapsulation and HMAC audit chaining. (Source: Author)}
    \label{fig:nonce_hmac}
\end{figure}

For forensic auditing, each adjudication record $D_i$ is cryptographically chained using HMAC-SHA256~\cite{hmac1997}:
\begin{equation}
    H_i = \text{HMAC-SHA256}(D_i \parallel H_{i-1}, K)
\end{equation}
where $H_{i-1}$ is the preceding record hash and $K$ is the local secret key. Modifying, inserting, or deleting records breaks chain continuity and is flagged instantly, ensuring tamper evidence.
