\chapter{System Design and Technical Implementation}
\label{ch:system_design_implementation}

This chapter elaborates on the architectural design and technical implementation solutions of the SENTINEL system. The content systematically details the two-tier execution pipeline, Tier 1 wire-speed filtration algorithms and Machine Learning Gate, Tier 2 agentic reasoning engine alongside Threat Memory, Dual-RAG knowledge retrieval, adversarial AI security controls and cryptographic audit sealing, and the local SOC dashboard deployment infrastructure.

\section{SENTINEL Architecture Overview and SOC Stack Integration}
\label{sec:architecture_overview}

To protect enterprise network infrastructure against high-density telemetry streams without incurring pipeline congestion, the SENTINEL system enforces a Cognitive Two-Tier Architecture. The core architectural design principle lies in strict operational decoupling: Tier 1 executes stateless statistical and machine learning algorithms to filter and offload at least 80\% of benign stream noise at wire-speed; Tier 2 hosts a stateful language model agent engine to perform deep contextual reasoning and adjudication for complex anomalous events.

Figure~\ref{fig:sentinel_flow} illustrates the detailed operational execution flow within the SENTINEL data pipeline. Raw network log telemetry generated by perimeter monitoring sources (NGFW, IPS, EDR) is ingested into a centralized Redis Stream queue. Immediately upon event arrival, Tier 1 computes online $Z$-score anomaly metrics using Welford's running statistical algorithm and classifies flow feature interactions through a LightGBM Machine Learning Gate. Traffic flows conforming to baseline distributions or matching repetitive payload templates stored in the Tier 1.75 Semantic Cache are adjudicated sub-millisecond, preserving GPU compute resources.

Only events classified as genuine anomalies escalate to Tier 2. Here, the LangGraph agent engine triggers a reasoning cycle executing a locally hosted Foundation-Sec-8B-Instruct model, integrating historical state from persistent Threat Memory and retrieved evidence from the Dual-RAG system. Final output decisions are governed by a deterministic Guardrail layer, strictly bounded to three explicit states (\texttt{BLOCK\_IP}, \texttt{LOG}, or \texttt{AWAIT\_HITL}). Every adjudication record is cryptographically sealed using HMAC-SHA256 hash chains to ensure forensic trail integrity and non-repudiation.

Within modern enterprise SOC architectures, SENTINEL functions as an intelligent cognitive middleware layer positioned between centralized SIEM log collectors (such as IBM QRadar) and downstream firewall/SOAR execution platforms (such as Palo Alto Cortex XSOAR). By absorbing massive stream noise at Tier 1 and providing grounded, transparent justifications for escalated events at Tier 2, SENTINEL eliminates alert flooding for security analysts while ensuring complete data sovereignty through 100\% air-gapped execution on a single 16\,GB VRAM GPU.

\section{Tier 1: Wire-speed Filter and Machine Learning Gate}
\label{sec:tier1_mlgate}

Tier 1 functions as the primary stateless perimeter defense layer processing stream telemetry at wire-speed. This layer combines Welford's $\mathcal{O}(1)$ statistical baseline filter with a LightGBM Machine Learning Gate to guarantee millisecond-level inference latencies and suppress stream noise prior to invoking GPU resources.

The statistical baseline filter continuously computes standard deviations $\sigma$ and real-time $Z$-score anomaly metrics across network flow attributes (packet rates, flow volumes, connection durations). Attribute $Z$-scores are calculated as $Z = (x - \mu) / \sigma$, where sample means $\mu$ and variances $\sigma$ are updated continuously via Welford's online algorithm without retaining raw event series in memory~\cite{welford1962}. Specifically, at each time step $k$, sample expectations $\mu_k$ and the sum of squared deviations $S_k$ are updated via the recurrence relations:
\begin{equation}
    \mu_k = \mu_{k-1} + \frac{x_k - \mu_{k-1}}{k}, \quad S_k = S_{k-1} + (x_k - \mu_{k-1})(x_k - \mu_k)
\end{equation}
enabling online evaluation of sample standard deviations $\sigma_k = \sqrt{S_k / (k-1)}$. Consequently, baseline flow traffic conforming to normal distributions is shed immediately. For repetitive volumetric intrusion attempts (such as DDoS attacks or automated brute-force attempts), the Tier 1.75 Semantic Cache hashes payload template structures in RAM, enabling 1-millisecond short-circuit response execution using cached decisions, terminating pipeline propagation prior to deep system ingestion.

A LightGBM Gradient Boosted Decision Tree model is integrated immediately following statistical filtration to evaluate non-linear flow feature interactions. Utilizing leaf-wise tree growth and histogram feature binning, LightGBM evaluates each NetFlow feature vector in approximately 0.35\,ms. To neutralize machine learning evasion tactics (anti-evasion), the Machine Learning Gate enforces feature $Z$-score clipping bounded within $\pm 8\sigma$ and imputes missing feature values using baseline mean metrics. If distorted feature proportions exceed 30\%, the Machine Learning Gate abstains from adjudication and automatically escalates the event to Tier 2 for deep contextual inspection.

\section{Tier 2: Stateful LangGraph Agent and Threat Memory}
\label{sec:tier2_agent_fsm}

Tier 2 performs stateful cognitive reasoning for anomalous events escalated from Tier 1. The reasoning engine executes a GGUF Q4\_K\_M quantized Foundation-Sec-8B-Instruct model~\cite{foundation_sec_2024} via llama.cpp compiled with CUDA acceleration on a single local 16\,GB VRAM GPU. The Q4\_K\_M quantization scheme reduces required VRAM from ~18\,GB (FP16 precision) to 7--8\,GB (>50\% memory savings) with negligible reasoning accuracy loss, enabling smooth model execution in air-gapped enterprise environments.

The agent reasoning workflow is orchestrated by a LangGraph Directed Acyclic State-Graph~\cite{langgraph2024}. Execution follows a deterministic sequence across five core processing nodes: initial guardrail inspection (\texttt{guardrails}), context enrichment (\texttt{rag\_context}), preliminary triage (\texttt{llm\_triage}), attack technique mapping (\texttt{attack\_mapper}), and action execution (\texttt{action\_executor} or \texttt{human\_in\_loop}). Technique mapping requires explicit verification from domain knowledge; if no unambiguous match is identified, the state graph routes the event to human analyst review (\texttt{AWAIT\_HITL}) rather than outputting speculative actions. Allowable output actions are strictly constrained to three states: \texttt{BLOCK\_IP}, \texttt{LOG}, or \texttt{AWAIT\_HITL}.

To correlate intrusion traces over extended periods, Tier 2 maintains persistent Threat Memory on an index-optimized SQLite database. Connection settings enforce normal synchronous mode with rollback-journal configuration to prevent cross-UID file lock crashes in Docker deployments. Threat Memory manages database tables tracking IP reputation histories, internal entities, risk indicators, and threat events. IP reputation scores $S$ decay naturally over silent periods $t$ according to:
\begin{equation}
    S_{\text{new}} = S_{\text{old}} \times (1 - \lambda)^t
\end{equation}
where $\lambda$ denotes the decay rate. When an IP address accumulates a maximum reputation score ($S = 100$), Tier 1 automatically enforces block-on-sight execution for subsequent connections without re-triggering Tier 2 LLM reasoning, closing an automated feedback loop. Conversely, internal infrastructure IP addresses (such as \texttt{10.0.0.99}) are hardcoded into a whitelist and remain immune to block actions to prevent self-DoS risks. This mechanism enables the agent to correlate multi-stage intrusion chains spanning multiple days.

\section{Dual-RAG Hybrid Knowledge Retrieval}
\label{sec:dual_rag}

To eliminate model hallucination and provide grounded forensic evidence for security decisions, Tier 2 incorporates a Dual-RAG hybrid knowledge retrieval system. The objective of this mechanism is to supply standardized domain knowledge from authoritative frameworks to the large language model during every reasoning cycle.

SENTINEL's security knowledge base is compiled from 432 STIX 2.1-structured MITRE ATT\&CK technique entries~\cite{strom2018mitre} and NIST SP 800-61r2 computer security incident handling guidance~\cite{nist80061}. Retrieval operates via two parallel, complementary search mechanisms: dense semantic vector search using FAISS~\cite{faiss2019} and sparse keyword matching using BM25~\cite{bm25_2009}. FAISS employs a Sentence-BERT embedding model~\cite{reimers2019sentence} to project telemetry queries into high-dimensional vector spaces for L2/Cosine distance matching, identifying attack techniques sharing semantic intent despite keyphrase variations. Conversely, BM25 computes term frequencies over sparse inverted indexes, ensuring exact retrieval of technical identifiers such as CVE codes, Registry keys, or service port numbers.

Retrieved candidate lists from both methods are consolidated using Reciprocal Rank Fusion (RRF)~\cite{rrf2009}:
\begin{equation}
    RRF\_Score(d) = \sum_{m \in \{\text{FAISS}, \text{BM25}\}} \frac{1}{k + r_m(d)}
\end{equation}
where $r_m(d)$ denotes the document rank in method $m$ and $k=60$ represents the smoothing constant. The top-ranked technique entries are compressed and injected directly into the prompt context at the \texttt{rag\_context} node. Consequently, the reasoning agent accurately maps anomalous telemetry to specific MITRE ATT\&CK technique identifiers while outputting verifiable forensic justifications for every adjudication decision.

\section{Adversarial AI Security and Cryptographic Audit Sealing}
\label{sec:ai_security_hmac}

Integrating large language models into cybersecurity infrastructure demands comprehensive adversarial defenses against log-substrate prompt injection attacks~\cite{promptinjection2023}. This vector involves attackers embedding malicious control instructions inside raw telemetry payload fields (such as User-Agent headers, URI parameters, or Syslog message text) to deceive the model and hijack its operational behavior.

To neutralize this threat vector, SENTINEL implements Delimited Data Encapsulation reinforced with session-unique cryptographic nonces~\cite{owasp_llm2025}. Raw log telemetry is entirely enclosed within nonce delimiters (e.g., \texttt{<<<DATA\_HASH...>>>}). This encapsulation forces the language model to process input payloads passively as plain data content, preventing the execution of embedded instruction triggers. Concurrently, label stripping removes internal classification tags from prompt inputs, eliminating internal state leakage. In parallel, a deterministic Guardrail layer strictly enforces Pydantic schema validation (\texttt{LLMDecision}); if output formatting errors occur, regular expression salvaging recovers essential decision fields or defaults to the safe \texttt{AWAIT\_HITL} state.

Complementing AI defenses, SENTINEL incorporates cryptographic audit sealing to guarantee non-repudiation for forensic evidence. Each security event record and adjudication decision $i$ is cryptographically signed using HMAC-SHA256 signature chaining~\cite{hmac1997}:
\begin{equation}
    H_i = \text{HMAC-SHA256}(D_i \parallel H_{i-1}, K)
\end{equation}
where $D_i$ denotes current record data, $H_{i-1}$ represents the preceding record hash signature, and $K$ is a local secret key. Chaining hash signatures produces a tamper-evident audit log trail; any unauthorized attempt to alter or delete historical log records breaks hash continuity and is flagged immediately.

\section{SOC Dashboard and On-Premises Deployment Architecture}
\label{sec:dashboard_deployment}

The SOC Analyst Dashboard is developed using Streamlit, connecting directly to Redis Stream queues and the Threat Memory database. The dashboard provides analysts with real-time operational visibility: Tier 1 processing throughput telemetry, multi-stage intrusion timeline visualization, HMAC audit chain integrity status, and a Human-in-the-Loop (HITL) review panel (\texttt{AWAIT\_HITL}).

The complete system services are fully containerized using Docker Compose (\texttt{docker-compose.yml}). The \texttt{llama.\allowbreak cpp} inference library is compiled with CUDA acceleration to leverage an NVIDIA RTX 4060 Ti 16\,GB VRAM GPU. The Threat Memory database (\texttt{threat\_memory.db}) and FAISS index are mounted on persistent Docker volumes, ensuring IP reputation scores and audit records survive container restarts.

Furthermore, deployment strictly adheres to Zero Trust mandates~\cite{nist80207}: database password strings in \texttt{REDIS\_URL} are redacted prior to logging. To manage high-density stream surges, the system enforces latency-based backpressure monitoring Redis consumer group lag, maintaining long-term pipeline stability.
