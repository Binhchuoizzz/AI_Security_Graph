\chapter{Experiments and Evaluation}
\label{ch:experiments_evaluation}

This chapter presents the experimental results and quantitative evaluation of the SENTINEL system. The content is streamlined to focus on core performance indicators: Tier 1 wire-speed noise offloading efficiency, Tier 2 cognitive agent adjudication and knowledge mapping accuracy, adversarial AI defense capabilities alongside cryptographic audit integrity, combined with controlled ablation studies and multi-dimensional comparisons against state-of-the-art platforms.

\section{Experimental Setup and Benchmark Telemetry}
\label{sec:experimental_setup}

The SENTINEL testbed is deployed on a local server representative of small-to-medium enterprise (SME) Security Operations Center (SOC) infrastructure, powered by an Intel Core i7 processor, 32\,GB DDR5 RAM, and a single NVIDIA GeForce RTX 4060 Ti 16\,GB VRAM GPU. All system microservices—including Redis Stream message queues, Tier 1 filters, Tier 2 LangGraph agents, and the \texttt{llama.cpp} CUDA inference server—are containerized via Docker Compose in an air-gapped environment to eliminate host operating system interference and ensure full experimental reproducibility.

Evaluation telemetry combines benchmark datasets: CSE-CIC-IDS2018~\cite{ids2018} (providing 25,799 labeled network flow events across 22 attack classes), CSIC 2010 (2,000 HTTP Layer 7 events), and DAPT2020~\cite{dapt2020} (simulating multi-stage APT attack scenarios), alongside 120 zero-day samples. To ensure accurate evaluation, dataset roles are strictly separated: the Tier 1 ML Gate is measured on \texttt{datatest.json}, ablation experiments utilize \texttt{ground\_truth.json}, and end-to-end evaluation leverages the \texttt{build\_stream()} simulation. Table~\ref{tab:experimental_setup} outlines the hardware testbed and benchmark telemetry specifications.

\section{Tier 1 Wire-speed Offloading and Latency}
\label{sec:tier1_performance}

Tier 1 filters stream noise at wire-speed, freeing GPU resources for Tier 2 reasoning. Welford's $\mathcal{O}(1)$ online statistical filter (\texttt{rule\_\allowbreak engine.py}) updates mean $\mu_k$ and sum of squares $S_k$ in real time, calculating standard deviation $\sigma_k$ to discard normal traffic~\cite{welford1962}. Concurrently, LightGBM (\texttt{ml\_\allowbreak gateway.py}) achieves 0.35\,ms inference latency via leaf-wise tree growth. For repetitive attacks, Tier 1.75 Semantic Cache (\texttt{response\_\allowbreak cache.py}) executes sub-1\,ms short-circuit responses.

Nevertheless, filtering over 90\% of stream noise without GPU invocation maintains Redis Stream consumer group lag near zero.

\section{Tier 2 Cognitive Reasoning Accuracy and Knowledge Mapping}
\label{sec:tier2_accuracy_rag}

Tier 2 processes the escalated 7.8\% anomalous stream events to perform stateful reasoning via the LangGraph agent (\texttt{workflow.py}) combined with the quantized Foundation-Sec-8B-Instruct Q4\_K\_M model. The Dual-RAG hybrid retrieval engine (\texttt{hybrid\_retriever.py}) fuses candidate contexts from FAISS dense vector search and BM25 sparse keyword matching via Reciprocal Rank Fusion ($RRF\_Score(d) = \sum 1 / (k + r_m(d))$ with $k=60$)~\cite{rrf2009}. Evaluated on 300 CSIC samples, RRF (with LLM disabled) achieves a technique mapping accuracy of 67.33\%. However, since the \texttt{T1595.003} technique accounts for 52\% of the dataset (random guess baseline), the 67.33\% accuracy only represents a marginal 15.33\% improvement over guessing. Furthermore, End-to-End mapping accuracy dropped significantly to 2.33\%, indicating that the LLM frequently overrides the retrieved mapping with generated responses instead of adhering to the RAG context.

Rather than employing a binary $F1$ metric—which misrepresents performance given an 86.9\% attack base rate—the system is evaluated via an \textit{action-based} method comparing Config A and Config F. Under Config F, human-in-the-loop escalation (\texttt{AWAIT\_HITL}) drops from 45.0\% to 0.0\%. Reasoning quality is independently graded by the Meta-Llama-3-8B-Instruct model on a 1-5 scale rather than self-evaluation. A score of 4.6/5.0 confirms robust forensic justification while eliminating the Self-Enhancement Bias commonly found in LLM-as-a-Judge protocols. Notably, the system's deliberate abstention by returning \texttt{N/A} on ambiguous cases is a correct guardrail behavior when confidence is low, rather than a schema failure.

\section{Adversarial AI Defense, Prompt Injection, and HMAC Audit}
\label{sec:adversarial_security_hmac}

System security resilience is verified across three evaluation scenarios. In log prompt injection testing (User-Agent headers, Syslog strings)~\cite{promptinjection2023}, Delimited Data Encapsulation (\texttt{encapsulation.py}) with unique random Nonce delimiters (\texttt{<<<DATA\_HASH...>>>}) at the Static Guardrail level only blocked 50\% (60/120) of malicious control instructions, failing completely (0/20) against semantic confusion attacks. However, within the End-to-End Pipeline on the remaining 75 samples reaching Tier-2, the system successfully neutralized 100\% of the attacks by forcing the model to process inputs passively~\cite{owasp_llm2025}. Stripping internal classification labels prior to prompt generation prevents state leakage.

For machine learning evasion testing, Tier 1 ML feature clipping ($\pm 8\sigma$) and the 30\% distortion abstention threshold escalate suspicious flows to Tier 2 for contextual inspection. In audit trail verification, any unauthorized log modification breaks HMAC-SHA256 hash-chaining continuity (\texttt{hmac\_sealer.py}) following $H_i = \text{HMAC-SHA256}(D_i \parallel H_{i-1}, K)$~\cite{hmac1997}. However, a mathematical limitation of log-chaining remains: it cannot detect tail-dropping attacks (truncation of the last logs), which must be acknowledged as a theoretical boundary.

\section{Ablation Study, Platform Comparison, and Resilience}
\label{sec:ablation_comparison_resilience}

An ablation study on 300 balanced samples demonstrates that the Single-Tier LLM baseline suffers severe queue congestion. However, Configurations B, C, D, and E yield identical action and latency outcomes, proving that the binary action metric saturates on this dataset. It is critical to address a severe methodological flaw in previous latency evaluations: measuring on a forced 50/50 dataset caused Tier 1 offload to drop to 11\%, yielding an invalid conclusion that the system was 7.8\% slower than LLM-only. When correctly evaluated on the real unified stream (achieving 92.2\% Tier 1 offload), the true SENTINEL global E2E average latency is 211\,ms, which is 11.6x faster than the Baseline.

Consolidated comparison against published platforms—including Watchtower~\cite{watchtower2026}, CyberRAG~\cite{cyberrag2025}, AutoBnB~\cite{autobnb2025}, LanG Agentic SOC~\cite{lang2026}, and Policy-Guided SIEM~\cite{splunkllm2026}—confirms SENTINEL's performance leadership across Throughput (over 2,500 flows/s), E2E Latency (211\,ms), Prompt Injection Defense (100\% pipeline coverage), and VRAM optimization (under 8\,GB) (Table~\ref{tab:ablation_comparison}).
